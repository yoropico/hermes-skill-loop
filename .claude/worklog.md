# worklog

One line per decision, the WHY not the what. Newest last.

Entries before 2026-07-30 happened in the `bomi-terminal` repo, where this loop was
originally built and deployed by the BCT terminal app; they are summarised here so
this repo is self-contained. The full history is in that repo's `.claude/worklog.md`
under the `[skill-loop]`, `[hermes-bct]`, `[curator-key-fix]`, `[curator-observ]` and
`[hermes-plugin]` tags.

2026-07-14 | [origin] Built as a port of the Hermes Agent Curator's DESIGN, not its code. Reusing Hermes itself was blocked (Anthropic routes third-party apps to the metered extra-usage pool, verified live HTTP 400) and, more decisively, Hermes is a separate agent whose skills live in ~/.hermes/skills where Claude Code never looks — so a Hermes learning loop improves Hermes, not the agent the work happens in. Since the intelligence lives in prompts + the model rather than in Hermes's algorithm, porting the design bought code independence (its version-ups cannot break us), automatic improvement by raising the model, and idea absorption as prompt diffs.
2026-07-14 | [recursion] Found a live infinite-recursion defect the landing review missed: SessionEnd -> learn.py shells out to `claude -p`, and `claude -p` ITSELF fires SessionEnd. Guarded with an env sentinel SKILL_LOOP_INTERNAL=1 set on every spawned call and checked at learn's entry. Rejected the docs' `reason` field as the guard — interactive normal exit is ALSO prompt_input_exit, so gating on it would silently drop the primary learn case. Also made `enabled: false` a real kill switch; it had been dead config on the hook path.
2026-07-15 | [two-stage-learn] Root-caused a bad outcome as a DESIGN gap, not a bad distill: learn could only create, so a later, better lesson forked a stale twin instead of correcting the original. Added the update pass (update.md sees the skill's current text and returns a merged body), plus an index of what we already know in the learn prompt so the model can choose update over create.
2026-07-30 | [curator-key-fix] Root-caused the curator as a LIVE NO-OP since its first commit: prompts/curate.md tells the model to reply [{"slug":...}] but apply_actions read act.get("skill"), so every action resolved to a None slug and was dropped. Evidence, not inference: _archive never existed after 16 days and ~16 runs on an expensive model, 32 of 63 learned skills never used and never triaged, while .curator_state kept stamping last_run so the loop LOOKED healthy. It survived review because the age-floor test fed the applier the real prompt key and then asserted only that the skill SURVIVED, crediting the floor for what was actually the key mismatch — it passed with min_age_days=0 too. Fix accepts both keys; the real deliverable is that the test is now differential (floor 7 vetoes, floor 0 actually archives) plus a contract test that parses the prompt's documented reply shape, so editing the prompt alone fails the suite.
2026-07-30 | [curator-observ] Made every silent path visible, because the defect above proved the failure mode is not "a bug" but "a bug nobody could see": `except Exception: return []` returned the same empty list for a dead model id, an unparseable reply, a pinned-skill veto, and a genuine keep-everything. New runlog.py appends one JSONL line per run and may never raise (it instruments the hooks; if it can break them it has become the problem it exposes). curate() RETURNS the record it logs so the two cannot disagree. Added --dry-run with plan_actions() splitting judgement from execution, so a preview runs the REAL decision instead of a parallel approximation free to drift; a preview ignores the interval guard and never stamps the clock.
2026-07-30 | [curator-observ] The first live --dry-run immediately paid for itself by exposing what 82 tests could not: the run log already held ten events nobody ran, because several tests call main() without redirecting log_target and so forged events into the user's real log — the exact artifact you consult to learn what the loop did. Isolation is now autouse in conftest rather than each test's job to remember. A diagnostic log the suite can forge is worse than no log.
2026-07-30 | [hermes-plugin] Extracted out of BCT into this standalone plugin repo. Verified before building rather than assumed: plugin hooks.json supports `matcher` (devmode uses it) and `async` (superpowers sets it explicitly), so usage keeps its Skill matcher and neither SessionEnd hook blocks session exit — no self-daemonising fork was needed. bootstrap.py was DELETED rather than ported: hook merging belongs to the manifest, and config seeding was unnecessary since every key already falls back to a built-in default, so settings.json is never touched at all.
2026-07-30 | [hermes-plugin] Moving the curator trigger from BCT's global-idle signal to a second SessionEnd hook forced out a REAL latent bug: curator.py never honoured SKILL_LOOP_INTERNAL (learn.py has since 07-14). Its own `claude -p` ends a session -> SessionEnd fires -> curator again, and the interval guard CANNOT stop it because .curator_state is stamped only after curate() returns, strictly later than the nested SessionEnd. Unreachable under the idle trigger, live under a SessionEnd trigger. RED test proved the recursion before the fix.
2026-07-30 | [hermes-plugin] Deployed and live-verified end to end. BCT's Release arm64 rebuild + signed bundle swap removed the payload (SkillLoopDeploy.deploy() overwrote ~/.claude/scripts/skill-loop on every launch, so a stale bundle would have silently reverted everything). migrate-off-bct.py then stripped the two legacy settings.json hooks and the payload dir, leaving 63 learned skills and the config untouched. After /plugin install + /reload-plugins, invoking one skill moved .usage.json from 66 to 67 entries with count exactly 1 — the plugin's PreToolUse(Skill) hook fired, once, and nothing else could have written it since the legacy wiring was gone.
2026-07-30 | [priorities] Shipped doctor, consolidate, cost signals and a slug fix in that order, chosen because the later items all presuppose the loop actually runs and the 16-day no-op showed that presupposition can be false. doctor's `reconciliation` check (proposed == kept + acted + skipped) is the one that justifies the script: arithmetic, not judgement, and nobody had to be clever to write it — it just had to exist. Its `hooks` check uses the log as evidence rather than guessing, since Claude Code's active hook table cannot be introspected but a learn/usage event can only exist because a hook fired.
2026-07-30 | [priorities] consolidate was the op the original spec promised and never shipped, which is why near-duplicates accumulated: archive was the only tool for two overlapping skills and it discards whatever the weaker one knew that the survivor did not — usually the specific detail that made it worth learning. The merge must succeed BEFORE anything moves, tested, because archiving first would on a failed merge leave the knowledge only in _archive/. `into` is required, since consolidating into nothing is a silent delete wearing another name.
2026-07-30 | [priorities] The slug fix carried a migration hazard worth more than the fix itself. Cutting at a word boundary means slugify and the old hard cut disagree for long names, so 14 skills already on disk would have stopped resolving — and every later lesson about them would have forked a stale twin, the exact failure the two-stage learn exists to prevent. learned_skill_path and write_skill therefore try both, existing-ours-wins, tested in both directions.
2026-07-30 | [priorities] Closed the "5 skills render with no description" investigation with evidence rather than a shrug: the listing refreshed mid-session and the affected SET CHANGED with no file touched, and it swept in unrelated third-party plugin skills. So Claude Code's listing assembly drops descriptions intermittently — which also explains why no distinguishing feature could be found across frontmatter keys, lengths, encodings or byte layout: there was none to find. Not ours to fix; doctor's descriptions check keeps the part we own honest.
2026-07-30 | [project] Made this repo a first-class project rather than something edited from a bomi-terminal worktree: CLAUDE.md carrying the invariants a future session could silently break (never delete, the x-origin firewall, every silent path logs, prompt/code agreement enforced by tests, py3.9 stdlib only, never rename an existing slug), docs/SPEC.md as the design of record with the Hermes pin, and this worklog seeded with the pre-extraction history so the repo is self-contained.
